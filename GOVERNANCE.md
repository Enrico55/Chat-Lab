# Governance

Humanity Commons is designed to resist capture by any single founder, company, government, model vendor, or node operator.

## Principles

1. Protocol changes are public and versioned.
2. Old protocol versions remain retrievable.
3. No maintainer may silently rewrite historical records.
4. Governance authority should be narrower than technical capability.
5. Forks are legitimate. Compatibility is encouraged, monopoly is not.
6. Automated systems may recommend; they do not receive unreviewable constitutional authority.

## Change process

Material protocol changes should use an HCP proposal under `protocol/` and include:

- problem statement;
- proposed change;
- compatibility impact;
- security impact;
- governance impact;
- migration path;
- alternatives considered.

Early experimental versions may merge rapidly, but stable versions should use public review windows and multiple maintainers from independent organizations.

## Future stewardship target

When the project has meaningful adoption, stewardship should move from a personal repository to a neutral legal/technical home with:

- multiple independent maintainers;
- transparent finances;
- published conflict-of-interest rules;
- no exclusive commercial license;
- reproducible releases;
- public governance history.

## Constitutional constraints

A compatible Humanity Commons implementation must not claim exclusive ownership over public protocol records, erase provenance to manufacture consensus, or represent one node's moderation decisions as universal truth.
